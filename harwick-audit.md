# Harwick Energy PLC — Scenario Logic Audit

**Scope:** AUDIT ONLY. No code or content was modified as part of this pass.

## Orientation

- **Events/scenarios:** [src/data/events.ts](src/data/events.ts) — 15 `GameEvent` objects (`event_01`…`event_15`), schema defined in [src/types/game.ts](src/types/game.ts) (`GameEvent`, `StrategyOption`, `OutcomeTierDefinition`, `FollowOnTrigger`).
- **Company/board shape:** [src/data/company.ts](src/data/company.ts) — `harwickEnergy` (id `company_harwick`). `inheritedBoard` is 4 seats (Okafor, Holt, Crane, Tanaka — all `role: 'ned'`; no inherited Chair, since the outgoing Chair Dame Helen Forsyth, `dir_00_forsyth`, is in `excludeDirectorIds` and marked "not available for reappointment"). `committees` starts with Remuneration `status: 'vacant'` and a note that a governance-health penalty for "no committee chair for 2 quarters" is already baked into the starting score — i.e. the Rem Chair vacancy is *disclosed backstory*, not a hidden fact the game reveals later (see event_01 discussion below).
- **Director data:** [src/data/directors.ts](src/data/directors.ts) — 23 Harwick directors (`dir_00_forsyth` … `dir_25_achebe`), including 4 inherited (`dir_08_crane`, `dir_12_tanaka`, `dir_13_okafor`, `dir_15_holt`) plus the excluded outgoing Chair `dir_00_forsyth`.
- **Board-state / lock mechanism:** [src/app/play/page.tsx](src/app/play/page.tsx) `BoardConstructionWrapper`. Seats default to `company.inheritedBoard` but are fully mutable pre-lock. `lockedDirectorIds` (the Rheinfeld-only protection mechanism, e.g. `['rdir_heinrich']`) is passed as `[]` for Harwick at both call sites ([page.tsx:1552](src/app/play/page.tsx:1552), [page.tsx:2196](src/app/play/page.tsx:2196)) — **Harwick has no locked/protected directors**. Any inherited director, including Geoffrey Crane (`dir_08_crane`) or Sir David Okafor (`dir_13_okafor`, the seeded Safety & Environment Chair), can be dropped or reassigned pre-lock, same as Meridian.
- **Precondition engine:** [src/engine/gameStateManager.ts](src/engine/gameStateManager.ts) `checkEventPrecondition()` (lines 202-341) and `checkEventCondition()` (lines 372-459). Harwick uses three precondition cases: `remChairVacant` (event_01, gates on `state.committees.remuneration.chairDirectorId === null` — a genuine board-state check), `harwick_greenvale_active` (event_10, gates on event_04's resolved outcome tier), and `harwick_proxy_battle` (event_15, gates on governance health < 50 AND event_10's outcome tier). **None of Harwick's three preconditions check whether a specific *named* director is still seated** — unlike Vantage's `vantage_nguyen_on_board` or SFG's `sfg_helena_on_board`, which gate directly on `state.board.seats.some((s) => s.directorId === '...')`. This matters because event_09 (AGM) and its debrief text center on Geoffrey Crane by name, yet no precondition exists for event_09 itself (it always fires as the fixed AGM slot) — instead the *runtime code* (page.tsx, AgmScreen.tsx, agmNarrative.ts) all independently re-derive `craneOnBoard` at the point of use. This is a materially better pattern than Meridian's hardcoded mevent_14 chair-swap bug — see "Reviewed, no material issues found" below — but it is done through ad hoc runtime checks rather than the declarative precondition/schema layer, so its correctness depends on every consuming file remembering to re-check, rather than being guaranteed once at the schema level.
- **Compliance rules:** [src/engine/compliance.ts](src/engine/compliance.ts) `checkComplianceUK()` (lines 70-255). Relevant codes: `NO_REM_CHAIR` (lines 141-146, `warning` severity, not blocking) fires whenever the Rem Chair seat is empty at lock — this is the same fact event_01's narrative escalates at Q1T1. Because company.ts already discloses the vacancy as pre-existing backstory (not a hidden reveal), and because `NO_REM_CHAIR` is only a warning (not a blocking error, unlike Meridian's `AUDIT_CHAIR_CONFLICT_RISK`), this is a **weaker** version of the Meridian pre-spoiler pattern: a player who fills the Rem Chair seat during construction removes the precondition entirely (event_01 correctly skips), and a player who leaves it vacant is not surprised by anything the event narrative subsequently claims. `NO_SID` (line 197, `warning`) is relevant to event_04/event_11/event_15's SID-referencing strategies (see findings). `checkTenureWarnings` (referenced line 243) flags Crane's 12-year tenure — consistent with, not contradicting, event_09's tenure narrative.
- **Event schema shape:** `narrativeCard: string` and `outcomeTiers[tier].narrative: string` are static prose, confirmed rendered verbatim by [EventCard.tsx](src/components/EventCard.tsx). No templating/interpolation layer exists. Names (Marcus Blaine, Priya Sundaram, Geoffrey Crane, etc.) are hardcoded literal strings.
- **boardEffect mechanism:** [src/types/game.ts](src/types/game.ts) `StrategyOption.boardEffect` (lines 190-197) is the schema hook for strategy-triggered director removals. **No Harwick event (`event_01`–`event_15`) uses `boardEffect`** — grep of `src/data/events.ts` confirms zero occurrences (it's used only in `meridian/events.ts` and `vantage/events.ts`). The only Harwick director removal tied to an event is a bespoke, correctly-gated inline mutation in `page.tsx` (see next bullet) rather than the generic `boardEffect` field.
- **Harwick-specific board mutation in page.tsx:** [page.tsx:609-614](src/app/play/page.tsx:609) — `handleResolveAgm`: `if (newState.company.id === 'company_harwick' && strategyChoice === 'event_09_b') { if (newState.board.seats.some((s) => s.directorId === 'dir_08_crane')) { Object.assign(newState, applyForcedRemoval(newState, 'dir_08_crane')); } }`. This **is correctly guarded** with a live board-state check before mutating — it does not reproduce the Meridian mevent_14 hardcoded-role-swap bug (which mutated roles unconditionally based on assumed identity). This is the one place worth calling out as done right, for contrast.
- **AGM content:** [src/components/AgmScreen.tsx](src/components/AgmScreen.tsx) — `craneOnBoard` is computed live at line 347 (`gameState.board.seats.some((s) => s.directorId === 'dir_08_crane')`) and used to select between `STRATEGIES_WITH_CRANE`/`STRATEGIES_WITHOUT_CRANE` (lines 32-86, 350-358), adjust vote math (`res1TenurePenalty`, line 364), and select debrief copy (lines 792-836, 798-804). [src/engine/agmNarrative.ts](src/engine/agmNarrative.ts) `generateAgmResolutionDebrief()` (lines 98-133) also re-derives Crane-specific copy from a `contextFlags.craneOnBoard` flag passed in by the caller. All three call sites agree and are independently correct — a genuinely good pattern, not a Meridian-style bug, but see the schema-hardness note below on why this had to be done three times instead of once.
- **Year-end debrief:** [src/components/YearEndScreen.tsx](src/components/YearEndScreen.tsx) — no Harwick-specific director-identity assumptions found; its Harwick-specific branch (line 268) is a cosmetic closing-CTA string only.

## Summary

**Counts by flaw type** (a finding can carry more than one tag):
- A (Board-state conflict): 0
- B (Premise conflict): 2 — event_01 (weak/mitigated), event_04/event_11/event_15 (SID reference)
- C (Stale display state): 1 — event_03 (Okafor pronoun)
- D (Sequencing/continuity): 2 — event_13 (unenforced probability claim), isGameOver cross-cutting
- E (General flaw): 0
- Unclassified: 1 — "Meridian Governance" naming collision

**Counts by suggested fix tier:**
- Tier 1 (precondition gate): 1 finding (event_04/event_11/event_15 SID reference, as an alternative fix)
- Tier 2 (dynamic name injection): 0 — Harwick's one genuine name-dependent event (event_09/Crane) already solves this correctly via ad hoc runtime lookups rather than needing a new templating layer
- Tier 3 (cut/replace or implement missing mechanic): 4 findings (event_03 pronoun, event_13's unenforced claim, "Meridian Governance" naming, isGameOver dead function)
- No fix needed / working as intended: event_01 (noted for awareness only), event_05/event_12/event_10/event_15's existing AUDIT-commented logic, event_09's Crane handling

**What makes Tier 1/2 fixes hard (generalizable engine/schema limitations):**

1. **No per-strategy-option existence gating.** As found in the Meridian pilot, `checkEventPrecondition()` only gates whether the whole `GameEvent` fires, with no equivalent check at the `StrategyOption` level. Harwick's SID-referencing strategies (event_04_c, event_11_b, event_15_a) would need a per-option `requiresRoleFilled: 'sid'` field to be hidden or reworded specifically when no SID is seated, rather than an all-or-nothing event-level precondition.
2. **Names/roles are hardcoded in prose, not templated.** Confirmed again for Harwick: `narrativeCard` and `outcomeTiers[*].narrative` are plain strings rendered verbatim by [EventCard.tsx](src/components/EventCard.tsx). There is no `{{seChairName}}` or `{{seChairPronoun}}`-style interpolation layer, so fixing event_03's pronoun bug "properly" (deriving the correct pronoun from whichever director actually holds `safetyEnvChair`) is not a one-line change — it requires either a templating pass, or rewriting the sentence to avoid gendered pronouns entirely (the lower-effort Tier 3 fix).
3. **Harwick's one correctly-solved case (Crane) required three independent re-implementations, not one.** `craneOnBoard` is computed separately in AgmScreen.tsx (line 347), agmNarrative.ts (passed in via `contextFlags.craneOnBoard`), and page.tsx (line 611) — three call sites that all happen to agree today only because each was hand-written carefully. There is no single source of truth (e.g. a memoized selector on `GameState`) that the schema forces all three to consume; a future edit to any one of them could silently reintroduce a Meridian-style divergence. This is the schema gap the pilot's fix-tier framework doesn't fully capture: it isn't "add a precondition" (there's nowhere for `AgmScreen`'s strategy-list logic to consult one), it's "the derived board-state fact needs to live in one place, not be re-derived ad hoc at every render/handler that needs it."
4. **`conditionDescription` is unstructured free text with no enforcement contract.** event_13's `conditionDescription: 'Probability increases if SV < 90 and Greenvale is active'` looks identical in shape to event_10's and event_15's `conditionDescription` strings, which *are* backed by real `precondition`/`conditionConfig` logic — but nothing in the schema distinguishes a documented-and-enforced conditional description from a purely aspirational one. A content author (or an LLM authoring new events) has no structural signal that this field needs a corresponding `precondition` case; the field's own presence looks equally trustworthy whether or not the claim is real.
5. **No generic win/loss-state hook.** `isGameOver()` exists but nothing calls it — there's no single phase-transition chokepoint in `page.tsx` that consults a generic "is the game over" predicate after every resolution. Wiring it up (or removing it) is a small, mechanical fix, but its existence as a silently-orphaned export is itself evidence that the engine has no enforced contract between "a state-ending condition is defined" and "something checks it every turn."
