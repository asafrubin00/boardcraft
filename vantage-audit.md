- **Director dynamics:** [src/data/vantage/dynamics.ts](src/data/vantage/dynamics.ts) — 6 pairwise synergy/friction modifiers, all keyed to generic domain-deployment triggers (e.g. "both deployed on activist or M&A events"), not to specific event IDs — no board-state fragility here.
- **Board-state / lock mechanism:** [src/app/play/page.tsx](src/app/play/page.tsx) `BoardConstructionWrapper` — seats default to `company.inheritedBoard` but are fully mutable pre-lock. Vantage has **no `lockedDirectorIds`** passed to `BoardroomTable` ([page.tsx:1552](src/app/play/page.tsx:1552); contrast Rheinfeld's `lockedDirectorIds={['rdir_heinrich']}` on the same line) — any inherited director, including Nguyen, Kellerman, Whitfield, or Park, can be dropped or reassigned pre-lock.
- **Precondition engine:** [src/engine/gameStateManager.ts](src/engine/gameStateManager.ts) `checkEventPrecondition()` ([gameStateManager.ts:202-341](src/engine/gameStateManager.ts:202)) and `checkEventCondition()` ([gameStateManager.ts:372-459](src/engine/gameStateManager.ts:372)). Vantage has **four** dedicated precondition cases: `vantage_nguyen_on_board` (real board-state gate — checks `state.board.seats.some(s => s.directorId === 'vdir_02_nguyen')`, [gameStateManager.ts:218-220](src/engine/gameStateManager.ts:218)), `vantage_apex_escalation`, `vantage_hostile_bid`, and `vantage_proxy_battle`. Only the first is a genuine board-composition check; the other three gate on scalar game-state flags (`apexActive`, `governanceHealth`), not on director identity. `checkEventCondition` additionally special-cases `vevent_10`/`vevent_15` to also require `apexActive` ([gameStateManager.ts:386-389](src/engine/gameStateManager.ts:386)).
- **Compliance rules:** [src/engine/compliance.ts](src/engine/compliance.ts) `checkComplianceUS()` ([compliance.ts:397-582](src/engine/compliance.ts:397)) — board-construction-time rules (NYSE §303A independence, SEC Rule 10A-3 audit-chair financial-expert threshold, combined Chair/CEO LID requirement). No Vantage-specific named-conflict code exists (no `AUDIT_CHAIR_CONFLICT_RISK` equivalent); instead the generic `AUDIT_CHAIR_NOT_INDEPENDENT` rule ([compliance.ts:465-472](src/engine/compliance.ts:465), `severity: 'error'`, `source: 'code'` since it doesn't match the `_LOW_` game-rule pattern) fires for *any* non-independent audit chair — including Nguyen if retained in that role, which is the functional equivalent of Meridian's Cavendish pre-spoiler.
- **Event schema shape:** `narrativeCard: string` and `outcomeTiers[tier].narrative: string` are static prose, rendered verbatim by [src/components/EventCard.tsx:144](src/components/EventCard.tsx:144) (`{event.narrativeCard}`). No templating/interpolation layer exists. Names are hardcoded directly into prose.
- **boardEffect mechanism:** [src/app/play/page.tsx:297-341](src/app/play/page.tsx:297) — generic, **not** hardcoded to a director ID. It reads `chosenStrategy.boardEffect.removeDirectorId` off the event data, checks `directorOnBoard` before applying, and supports `simultaneousRemoveIds`. `vevent_01_a`'s `boardEffect` ([events.ts:32-37](src/data/vantage/events.ts:32)) uses this mechanism correctly — no mevent_14-style hardcoded-director-ID bug exists in Vantage's board-construction wrapper.
- **AGM content:** [src/components/AgmScreen.tsx](src/components/AgmScreen.tsx) — Vantage-specific resolution panels ([AgmScreen.tsx:508-531](src/components/AgmScreen.tsx:508)) and vote-adjustment math ([AgmScreen.tsx:398-410](src/components/AgmScreen.tsx:398)) reference only `gameState.apexActive`, `gameState.apexStatus`, and `gameState.chairCeoSeparationProgress` — scalar flags, not director identities — so there is no AGM-side board-state fragility of the Meridian/Cavendish kind. However, see the dead-variable findings below: two of these three flags never change from their initial values.
- **Follow-on/queue mechanism:** `resolveEvent()` computes `output.followOnEvents` from `event.followOnTriggers` ([src/engine/resolution.ts:337-349](src/engine/resolution.ts:337)) and `applyResolution()` appends them to `state.eventQueue` ([gameStateManager.ts:577](src/engine/gameStateManager.ts:577)). `getFollowOnEvents(state)` reads that queue ([gameStateManager.ts:463-472](src/engine/gameStateManager.ts:463)) but **is never called from `page.tsx`** — confirmed via repo-wide grep. Vantage's actual event gating runs entirely through the fixed `eventSchedule` slot + `checkEventPrecondition`/`checkEventCondition`, not through this queue. `vevent_02`'s and `vevent_10`'s `followOnTriggers` arrays are therefore vestigial.

### Nguyen precondition consistency check (explicitly requested)

**Not applied consistently — but not in the direction Meridian's audit found.** Unlike Meridian (which had zero board-state preconditions), Vantage's `vantage_nguyen_on_board` precondition is a real, correctly-implemented guard, and it is the *only* Vantage precondition keyed to a specific director's board presence. Checking every other event that names or presupposes a specific seated director:

- **Sandra Okafor** (combined Chair/CEO) — named in `vevent_02`, `vevent_03`, `vevent_05`, `vevent_10`, `vevent_13`, `vevent_15`. She is a fixed executive NPC (`company.executives`), **not** a seatable/removable `Director` — there is no `vdir_*` ID for her and no seat she occupies, so no board-state precondition is needed or missing here. This mirrors Meridian's CEO Finch/CFO Woolley treatment and is correctly out of scope.
- **No other Vantage event names a specific seatable director as its subject.** `vevent_06` (supply chain), `vevent_07` (UPF tax), `vevent_11` (brand crisis), `vevent_12` (FTC/M&A), `vevent_14` (data breach) all reference committees, roles, or fixed NPCs (CISO, General Counsel, CMO) generically, not named seated directors. `vevent_09` (AGM) references "the Lead Independent Director" and "Comp Committee Chair" **by role**, not by name — whoever holds `sid`/`remChair` at the time is implicitly who acts, which is the correct generic pattern and requires no precondition.
- Therefore the *board-state-existence* precondition pattern is applied to the one event that actually needs it (vevent_01/Nguyen) and correctly omitted elsewhere, because no other event has an equivalent dependency. The **inconsistency that does exist** is different from Meridian's: it's in the `conditionDescription` layer, not the director-identity layer — `vevent_10` and `vevent_15` both carry copy describing an "OR AGM Resolution 3 failed" trigger clause that has no corresponding code in `checkEventPrecondition`/`checkEventCondition` (see findings table above). So: the specific pattern the task asked to check for (a named-director precondition applied to only one event and missing elsewhere) does **not** recur in Vantage — vevent_01/Nguyen is correctly the only case requiring it. The consistency problem that does exist is narrower and lower-severity than Meridian's.

### Reviewed, no material issues found

vevent_02, vevent_03, vevent_04, vevent_06, vevent_07, vevent_11, vevent_12, vevent_14 — these reference generic executive NPCs (Sandra Okafor, Marcus Chen/CFO, Brianna Walsh/CMO, David Ruiz/General Counsel, Amara Patel/CPO — all fixed narrative characters, not seatable/removable directors), unnamed committee roles, or external parties (Apex Capital's Marcus Adler, Meridian Governance, FDA, FTC, Constellation Foods) that are not board seats and require no board-state precondition. Their strategy competency gates are generic domain-threshold checks (`{ domain, minimumRating }`) that work correctly regardless of which specific directors are seated — if no qualified director exists, `EventCard.tsx`'s `gateStatus` computation ([EventCard.tsx:68-92](src/components/EventCard.tsx:68)) correctly locks the strategy rather than assuming a specific director fills it. `vevent_13`'s and `vevent_09`'s strategy options were checked individually for named-director dependency and found to reference only roles/NPCs. The `vantageDynamics` pairwise director synergies ([dynamics.ts](src/data/vantage/dynamics.ts)) are all generic domain-deployment triggers, not event-specific, and require no precondition of their own.

## Summary

**Counts by flaw type** (a finding can carry more than one tag):
- A (Board-state conflict): 0
- B (Premise conflict): 1 — vevent_01 (compliance/risk-flag pre-spoiler sub-case)
- C (Stale display state): 1 — EventCard "Meridian Governance Report" hardcoded label (minor/coincidental, not currently player-visible as broken)
- D (Sequencing/continuity): 2 — vevent_10, vevent_15 (unenforced "OR Resolution 3 failed" clause)
- E (General flaw): 2 — vevent_13 (unenforced probability claim), vevent_09 (unenforced concession-strategy claim)
- Unclassified: 0

**Counts by suggested fix tier:**
- Tier 1 (precondition gate): 0 — Vantage's one board-state-dependent event (vevent_01) is already correctly gated; no missing Tier 1 fixes identified
- Tier 2 (dynamic name injection): 0 — no event was found presupposing a specific seated director without a working gate, so no dynamic-name-injection fix is needed for board composition. (The schema-hardness reasons this would still be hard if a Tier 2 case existed are noted below.)
- Tier 3 (cut/replace or implement missing mechanic): 7 findings — vevent_01 (soften pre-spoiled framing), vevent_10 (cut/implement OR-clause), vevent_13 (cut/implement probability claim), vevent_15 (cut/implement OR-clause), vevent_09 (soften/implement concession-strategy claim), EventCard hardcoded label, plus the four dead-state fields (`apexStatus`, `chairCeoSeparationProgress`, `apexActive`, `fdaInquiryActive`) as a bundled Tier 3 item

**Headline difference from the Meridian pilot:** Vantage's board-composition layer is materially more robust than Meridian's — it has a real, correctly-scoped board-state precondition (`vantage_nguyen_on_board`), a generic non-hardcoded `boardEffect`/`removeDirectorId` mechanism (no mevent_14-style hardcoded-ID bug), and no other event was found presupposing a seated director without a working gate. The defects that do exist have shifted up a layer: from "narrative assumes a director is still seated" (Meridian's dominant pattern) to "narrative/conditionDescription copy asserts a game-state mechanic (Apex neutralisation, Chair/CEO separation progress, probability-weighted firing, a Resolution-3-outcome OR-clause) that the engine never actually implements." Four scalar `GameState` fields purpose-built for the Apex/Chair-CEO storyline are wired up to be *read* in several places but are never *written* anywhere, making several outcome narratives permanently decorative.

**What makes Tier 1/2 fixes hard:**
1. **No per-strategy-option existence gating.** Same limitation as Meridian: `checkEventPrecondition` only gates whether the whole `GameEvent` fires; there is no equivalent check at the `StrategyOption` level. This didn't bite any Vantage event in this audit (no strategy option was found naming a specific seated director), but it remains a latent gap — if a future Vantage event or content update added a strategy like "Ask Kellerman to broker the deal personally," there would be no schema-level way to hide that option if Kellerman were removed pre-lock without a bespoke `requiresSeated`/`requiresDirectorId` field.
2. **Names are hardcoded in prose, not templated.** `narrativeCard` and `outcomeTiers[*].narrative` are plain `string` fields rendered verbatim ([EventCard.tsx:144](src/components/EventCard.tsx:144)). No `{{leadIndependentDirectorName}}`-style interpolation layer exists. Vantage's copy is more defensive about this than Meridian's — it mostly uses role references ("the Lead Independent Director," "your CISO," "General Counsel") rather than director names — but this is a content-authoring discipline, not a schema guarantee; nothing prevents a future event from hardcoding a director's name the way Meridian's mevent_01/03/08/14 did.
3. **Scalar game-state flags can be added to `GameState` and referenced in read-sites (UI, AGM math, narrative generators) without any enforcement that a corresponding write-site exists.** This is the dominant failure mode found in this audit: `apexStatus`, `chairCeoSeparationProgress`, and `apexActive`-going-false all have multiple consumers but zero producers. The schema and type system provide no signal that a field is "read-only by construction" — a `GameState` field looks the same whether or not any code path ever assigns it a non-default value, so this class of bug is invisible to TypeScript's type checker and only surfaces via full-repo grep for write-sites.
4. **`conditionDescription` is free-text documentation of a condition, not a source of truth for it.** `conditionConfig` (the actual enforced gate) and `conditionDescription` (the human-readable copy shown to players via strategy descriptions and dev tooling) are two independent fields with no consistency check between them. Nothing fails to compile or breaks a test if `conditionDescription` claims a richer condition than `conditionConfig`/`checkEventPrecondition` actually implements — which is exactly what happened on vevent_10 and vevent_15's "OR AGM Resolution 3 failed" clauses.
5. **Compliance rules and event narrative are not synchronized**, same structural gap as Meridian. `compliance.ts`'s `AUDIT_CHAIR_NOT_INDEPENDENT` already "knows" a non-independent audit chair is a live problem the moment board construction starts, and Nguyen's own `riskFlag` data field discloses the exact conflict `vevent_01` later narrates as a fresh revelation — but the event data has no awareness that this disclosure may already have happened for every player, not just ones who kept her in the role.
