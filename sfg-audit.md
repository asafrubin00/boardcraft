# Straits Financial Group (SFG) — Scenario Logic Audit

**Scope:** AUDIT ONLY. No code or content was modified as part of this pass.

## Orientation

- **Events/scenarios:** [src/data/sfg/events.ts](src/data/sfg/events.ts) — 15 `GameEvent` objects (`sfgevent_01`…`sfgevent_15`), schema defined in [src/types/game.ts](src/types/game.ts) (`GameEvent`, `StrategyOption`, `OutcomeTierDefinition`, `FollowOnTrigger`). Code comments in the events file itself label each event `SFG-01`…`SFG-15` matching the `sfgevent_NN` numbering 1:1 (e.g. the comment at [events.ts:9](src/data/sfg/events.ts:9) reads `// SFG-01 — Audit Committee Chair Vacancy: MAS Notices` directly above `sfgevent_01`).
- **Company/board shape:** [src/data/sfg/company.ts](src/data/sfg/company.ts) — `inheritedBoard` (5 starting seats: Lim as chair, Soong as SID, Goh as remChair, Rahman as NED, Png as NED — [company.ts:134-140](src/data/sfg/company.ts:134)), `committees` (six committees; **Audit Committee status is `'vacant'`, `chairDirectorId: null` at [company.ts:76-84](src/data/sfg/company.ts:76)** — the inherited board starts with no AC Chair at all), `eventSchedule` (event → quarter/turn mapping, [company.ts:141-157](src/data/sfg/company.ts:141)).
- **Director data:** [src/data/sfg/directors.ts](src/data/sfg/directors.ts) — `Director[]`, 5 inherited + 22 candidates. Confirmed: **Lee Siew ("Geok") Geok** exists as `sfgdir_06_lee` ([directors.ts:180-204](src/data/sfg/directors.ts:180), "the highest-credibility Audit Committee Chair candidate in the pool") and **Helena Soong Hui Ling** exists as `sfgdir_02_soong` ([directors.ts:50-81](src/data/sfg/directors.ts:50), inherited SID/NC Chair/BCC Chair, tenure 10 years — exceeds the 9-year SGX cap). Both are recruitable/inherited, not fixed narrative NPCs — both are removable/replaceable pre-lock.
- **Board-state / lock mechanism:** [src/app/play/page.tsx](src/app/play/page.tsx) `BoardConstructionWrapper` — seats default to `company.inheritedBoard` but are fully mutable (drag/drop, remove, reassign role, recruit from the candidate pool) until "Lock Board." Only Eric Png (`sfgdir_05_png`, Temasek nominee) is explicitly protected — his bio states "cannot be removed by player" ([directors.ts:147](src/data/sfg/directors.ts:147)) — no other inherited SFG director (Lim, Soong, Goh, Rahman) is locked. This confirms the same mutability pattern as Meridian: players are free to appoint a new AC Chair (e.g., Lee Siew Geok) or remove/replace Soong/Goh/Lim entirely pre-lock.
- **Precondition engine:** [src/engine/gameStateManager.ts](src/engine/gameStateManager.ts). There are **two separate gate mechanisms** and SFG uses both, inconsistently:
  - `checkEventPrecondition()` ([gameStateManager.ts:202-341](src/engine/gameStateManager.ts:202)) — keyed on the literal `event.precondition` string via a `switch`. None of the eight `sfg_*` precondition strings used in `src/data/sfg/events.ts` (`sfg_helena_on_board`, `sfg_no_sustainability_committee`, `sfg_temasek_concern_active`, `sfg_renewal_not_addressed`, `sfg_ceo_whistleblower_substantiated`, `sfg_governance_weak_sv_low`, `sfg_enforcement_precondition`, `sfg_lim_chair_unresolved`) has a matching `case` in this switch — they all silently fall through to `default: return true` here.
  - `checkEventCondition()` ([gameStateManager.ts:372-459](src/engine/gameStateManager.ts:372)) — the actual gate for these eight strings, but keyed on **`event.id`** (a `switch (event.id)` block at line 394), not on the `event.precondition` string value itself. The `case` labels (lines 414-454) happen to be named identically to the precondition strings, which is why the mechanism still works — `getCurrentEvent()` calls `checkEventPrecondition` first (returns `true` for all SFG conditionals) and then, because every one of these events also sets `isConditional: true`, calls `checkEventCondition` second, which does the real per-event-ID board-state check. **Net effect: the gates for `sfgevent_02/07/08/09/10/11/12/15` do function correctly at runtime**, but only because of this two-tier indirection — `checkEventPrecondition`'s `sfg_*` cases are entirely absent (dead switch arms by omission), unlike Vantage/Rheinfeld/Meridian's precondition strings, which mostly do have direct cases in `checkEventPrecondition`. **`sfgevent_01` and `sfgevent_03` (Q1T1, Q1T3) and `sfgevent_04`/`sfgevent_06`/`sfgevent_13`/`sfgevent_14` have `isConditional: false, precondition: null` — no gate of any kind.**
- **Compliance rules:** [src/engine/compliance.ts](src/engine/compliance.ts) `checkComplianceSG()` ([compliance.ts:589-728](src/engine/compliance.ts:589)) — board-construction-time MAS/SGX rules. Directly relevant: **`SG-MAS-002`** ([compliance.ts:648-655](src/engine/compliance.ts:648)) is a blocking `error` fired if `!committees.audit?.chairDirectorId` — i.e., the exact same vacancy `sfgevent_01` is about — surfaced to the player *during board construction*, before the game even starts. `SG-MAS-004` ([compliance.ts:685-691](src/engine/compliance.ts:685)) flags Dato' Lim's dual Chair/BRC role (relevant to `sfgevent_05`/`sfgevent_15`). `SG-SGX-002` ([compliance.ts:625-635](src/engine/compliance.ts:625)) flags any independent director at/over the 9-year tenure cap (relevant to `sfgevent_02`/`sfgevent_13`, Soong and Goh specifically).
- **Event schema shape:** `narrativeCard: string` and `outcomeTiers[tier].narrative: string` are static prose — no templating/interpolation mechanism exists (confirmed: [EventCard.tsx](src/components/EventCard.tsx:144) renders `{event.narrativeCard}` verbatim, same as Meridian). Names are hardcoded directly into prose. `StrategyOption.competencyGates` ([resolution.ts:227-237](src/engine/resolution.ts:227)) check only `Math.max(...deployedDirectors.map(d => d.domainRatings[gate.domain]))` against a numeric threshold — **there is no per-strategy check of a specific director's presence on the board or in a specific committee role**, confirmed by reading the full gate-resolution logic in [resolution.ts](src/engine/resolution.ts).
- **Board-construction hardcoded mutations:** grep of `src/app/play/page.tsx` for `sfgevent_0[1-9]|sfgevent_1[0-5]` found exactly one event-specific mutation block: `sfgevent_04` ([page.tsx:394-408](src/app/play/page.tsx:394)), which sets `newState.ceoWhistleblower` based on outcome tier + chosen strategy — this one is genuinely wired and mutated correctly (Type-safe, not a dead field). No equivalent of Meridian's mevent_14 hardcoded-directorId chair-swap bug exists in SFG's page.tsx — none of the SFG events perform a hardcoded `if (s.directorId === 'sfgdir_...')` role mutation.
- **AGM/debrief content:** [src/components/AgmScreen.tsx](src/components/AgmScreen.tsx) has bespoke SFG logic ([AgmScreen.tsx:308](src/components/AgmScreen.tsx:308) `isSfg`, [AgmScreen.tsx:425-470](src/components/AgmScreen.tsx:425) two-tier vote math). The Resolution 1 two-tier vote is computed dynamically from `board.seats` filtered by `tenure > 9` ([AgmScreen.tsx:428-431](src/components/AgmScreen.tsx:428)) — this is a robust, board-state-driven pattern with **no hardcoded director IDs**, unlike some of the event narrative. However, Resolution 2's vote math reads `gameState.acChairVacant` directly ([AgmScreen.tsx:462](src/components/AgmScreen.tsx:462)) — see SFG-02 below.
- **State fields specific to SFG:** [src/types/game.ts:444-448](src/types/game.ts:444) — `acChairVacant: boolean`, `masLetterOpen: boolean`, `ceoWhistleblower: 'pending' | 'substantiated' | 'cleared' | null`. Initialized in [gameStateManager.ts:155-157](src/engine/gameStateManager.ts:155): `acChairVacant: co.id === 'company_sfg'` (always `true`, unconditionally, regardless of board composition at lock time), `masLetterOpen: co.id === 'company_sfg'` (also always `true`), `ceoWhistleblower: 'pending'`. Full-repo grep confirms `ceoWhistleblower` is the only one of the three ever mutated post-init (via `sfgevent_04`'s resolution in page.tsx). `acChairVacant` and `masLetterOpen` have **no write path anywhere in the codebase** after initialization — see SFG-02.

**SFG-01 and SFG-02, confirmed:**
- **SFG-01** = `sfgevent_01` ("MAS Notices: Audit Committee Chair Vacancy," Q1 Turn 1). Confirmed via code: `isConditional: false`, `precondition: null` ([events.ts:93-94](src/data/sfg/events.ts:93)) — it fires unconditionally on schedule, with no check of `state.committees.audit.chairDirectorId` (which the engine does populate correctly from board construction, per [gameStateManager.ts:69](src/engine/gameStateManager.ts:69)). It fires identically whether the AC Chair seat is genuinely vacant or already held by Lee Siew Geok (or any other director the player assigned pre-lock) — a pure Type-B premise conflict, additionally pre-spoiled by the blocking `SG-MAS-002` compliance error shown during board construction.
- **SFG-02** = the dead `acChairVacant` state field (declared [types/game.ts:444](src/types/game.ts:444), initialized `true` for every SFG game at [gameStateManager.ts:155](src/engine/gameStateManager.ts:155), never mutated anywhere thereafter — confirmed by exhaustive grep). This label was **not found pre-documented anywhere else in the repo** — it is inferred from this audit as the clearest second instance in the same "vacancy premise ignoring player resolution" family, and was selected over other candidates (e.g. sfgevent_07's named-candidate gap, sfgevent_09's tenure-inference issue) because it has the highest severity: it silently corrupts a live numeric AGM vote calculation (Resolution 2, a -15 vs +8 swing) in every single SFG playthrough, regardless of what the player actually did about the AC Chair vacancy. A sibling dead field, `masLetterOpen` (also hardcoded `true`, [gameStateManager.ts:156](src/engine/gameStateManager.ts:156)), is even more inert — it has no reader anywhere in the codebase at all.

**No "GAME OVER" strings found** in `src/data/sfg/events.ts` or `src/components/AgmScreen.tsx`'s SFG-specific branches (confirmed by direct grep) — SFG does not exhibit Meridian's "unenforced GAME OVER copy" pattern.

**What makes Tier 1/2 fixes hard:**
1. **No per-strategy-option existence gating**, identical to the Meridian finding. `checkEventPrecondition`/`checkEventCondition` only gate whether the whole `GameEvent` fires — there is no equivalent check at the `StrategyOption` level. `sfgevent_01_a`, `sfgevent_07_a`/`_b`, and `sfgevent_15_a`/`_b` all name specific candidate directors directly in their `label`/`description` fields, but [resolution.ts:227-237](src/engine/resolution.ts:227) only ever checks aggregate numeric `domainRatings` across whichever directors the player happens to deploy — never a specific `directorId`. Even with an event-level precondition, a naive fix would still let the player pick "Appoint Lee Siew Geok" and get her outcome narrative while deploying someone else entirely, unless the schema grows a per-option `requiresDirectorId`/`requiresSeated` field.
2. **Names are hardcoded in prose, not templated** — same as Meridian and every other company. `narrativeCard` and `outcomeTiers[*].narrative` are plain `string` fields rendered verbatim ([EventCard.tsx:144](src/components/EventCard.tsx:144)). There is no `{{acChairName}}`-style interpolation layer. SFG's AGM screen (`AgmScreen.tsx`) is the one exception — it computes its own dynamic paragraphs from live board state rather than relying on the static `GameEvent.narrativeCard` for `sfgevent_13`, which is why sfgevent_13's static narrative field is more of a latent/dead-copy risk than an active player-facing bug (see finding table).
3. **Two parallel precondition mechanisms create a false sense of coverage.** SFG's precondition strings (`sfg_helena_on_board`, etc.) are absent from `checkEventPrecondition`'s switch entirely and only resolved via `checkEventCondition`'s parallel `switch (event.id)` block. This works today because every SFG event using these strings also sets `isConditional: true`, but it means the `event.precondition` field and the `checkEventPrecondition` function are misleading by omission for this company — a future refactor that "cleans up" `checkEventCondition` without noticing this dependency could silently break every conditional SFG event. This is a structural inconsistency versus Vantage/Rheinfeld/Meridian, which mostly implement their precondition strings directly in `checkEventPrecondition`.
4. **Compliance rules and event narrative are not synchronized**, same root cause as Meridian's Cavendish case. `checkComplianceSG()`'s `SG-MAS-002` already "knows" whether the AC Chair is vacant at construction time and surfaces it as a blocking error — but `sfgevent_01` has no awareness that this disclosure, and possibly a full resolution, may have already happened by the time Q1 Turn 1 fires.
5. **Dead state fields with no update path, now with a live numeric consequence.** `acChairVacant` and `masLetterOpen` both exist on `GameState` purely as write-once-at-init flags. Unlike Meridian's dead fields (which only gated unreachable narrative branches), `acChairVacant` is read by `AgmScreen.tsx` and directly changes a vote-share calculation shown to every player at the AGM — meaning this is not merely a copy-consistency bug but a numeric fairness bug: the AGM's Resolution 2 always assumes the worst-case (vacancy still open) regardless of how well the player actually handled `sfgevent_01` in Q1. Any Tier 1/3 fix addressing SFG-01 should also thread the resolution outcome through to flip `acChairVacant` to `false`, or eliminate the field and derive the AGM adjustment directly from `state.committees.audit.chairDirectorId` at the time the AGM fires.
