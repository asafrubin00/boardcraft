# Meridian Foundation — Scenario Logic Audit (Pilot)

**Scope:** AUDIT ONLY. No code or content was modified as part of this pass.

## Orientation

- **Events/scenarios:** [src/data/meridian/events.ts](src/data/meridian/events.ts) — 15 `GameEvent` objects (`mevent_01`…`mevent_15`), schema defined in [src/types/game.ts](src/types/game.ts) (`GameEvent`, `StrategyOption`, `OutcomeTierDefinition`, `FollowOnTrigger`).
- **Company/board shape:** [src/data/meridian/company.ts](src/data/meridian/company.ts) — `inheritedBoard` (5 starting trustee seats), `committees`, `eventSchedule` (event → quarter/turn mapping).
- **Trustee data:** [src/data/meridian/trustees.ts](src/data/meridian/trustees.ts) — `Director[]`, including the 5 inherited trustees (Mensah, Osei-Bonsu, Ashworth, Al-Rashid, Cavendish) and 12 candidate trustees.
- **Board-state / lock mechanism:** [src/app/play/page.tsx](src/app/play/page.tsx) `BoardConstructionWrapper` — seats default to `company.inheritedBoard` but are fully mutable (drag/drop, remove, reassign role) until "Lock Board." Unlike Rheinfeld (`lockedDirectorIds={['rdir_heinrich']}`), **Meridian has no locked/protected director IDs** — any inherited trustee, including Cavendish, Osei-Bonsu, or Mensah-as-chair, can be dropped or reassigned pre-lock.
- **Precondition engine:** [src/engine/gameStateManager.ts](src/engine/gameStateManager.ts) `checkEventPrecondition()` (event-level gate keyed on `event.precondition` string) and `checkEventCondition()` (outcome-chain gate keyed on `event.conditionConfig`). Other companies use `checkEventPrecondition` to gate on **board-state existence** (e.g. `vantage_nguyen_on_board`, `sfg_helena_on_board`, `heinrichBlocks`). **None of Meridian's three precondition cases do this** — `mevent_02_partial_or_worse`, `mevent_01_partial_or_worse`, `mevent_09_fss_or_event03` all check prior *event outcomes*, never whether a named trustee is actually seated.
- **Compliance rules:** [src/engine/compliance.ts](src/engine/compliance.ts) `checkComplianceCharityUK()` — board-construction-time rules (independence, tenure, committee chair fitness). Relevant: `AUDIT_CHAIR_CONFLICT_RISK` is a blocking `error` triggered by Cavendish's `independence: 'questionable'` status while he holds `auditChair` — see Finding on mevent_01 below.
- **Event schema shape:** `narrativeCard: string` and `outcomeTiers[tier].narrative: string` are static prose — no templating/interpolation mechanism exists (confirmed: [EventCard.tsx](src/components/EventCard.tsx) renders `{event.narrativeCard}` verbatim). Names are hardcoded directly into prose, not injected from `state.board.seats` / `state.directors`.

## Summary

**Counts by flaw type** (a finding can carry more than one tag):
- A (Board-state conflict): 5 — mevent_01, mevent_08, mevent_14, mevent_03, mevent_09
- B (Premise conflict): 2 — mevent_01 (compliance-spoiler sub-case), mevent_04
- C (Stale display state): 2 — mevent_14, FSS cross-cutting
- D (Sequencing/continuity): 5 — mevent_08, mevent_09, mevent_14, FSS cross-cutting, GAME OVER cross-cutting, mevent_01 sub-case
- E (General flaw): 2 — mevent_09 (unenforced Mensah claim), GAME OVER cross-cutting
- Unclassified: 0

**Counts by suggested fix tier:**
- Tier 1 (precondition gate): 6 findings (mevent_01, mevent_08, mevent_14, mevent_03, mevent_09, mevent_04)
- Tier 2 (dynamic name injection): 0 standalone — recommended as a *complement* to Tier 1 on mevent_09/mevent_14 rather than a substitute, given schema limitations below
- Tier 3 (cut/replace): 4 findings (FSS mechanic, GAME OVER copy, mevent_01 sub-case, plus mevent_09's unenforced Mensah claim as an alternative to implementing it)

**What makes Tier 1/2 fixes hard:**
1. **No per-strategy-option existence gating.** `checkEventPrecondition` only gates whether the whole `GameEvent` fires — there is no equivalent check at the `StrategyOption` level. mevent_14's strategies C/D name Osei-Bonsu directly; even with an event-level precondition added, a naive implementation would still offer those specific options when she's gone unless the schema grows a per-option `requiresDirectorId`/`requiresSeated` field.
2. **Names are hardcoded in prose, not templated.** `narrativeCard` and `outcomeTiers[*].narrative` are plain `string` fields rendered verbatim ([EventCard.tsx](src/components/EventCard.tsx)). There is no `{{chairName}}`-style interpolation layer, so a Tier 2 "dynamic name injection" fix is not a small patch — it requires adding a templating pass between the data layer and the render layer, then rewriting every affected string to use placeholders instead of literal names ("Robert Cavendish," "Dr. Evelyn Osei-Bonsu," "Patricia Mensah" all appear as literal text).
3. **`boardEffect` mutations are hardcoded to specific `directorId`s**, not to "whoever currently holds role X." mevent_14's chair swap ([page.tsx:359-366](src/app/play/page.tsx:359)) is the clearest example — it should look up `board.seats.find(s => s.role === 'chair')` dynamically rather than assuming `mdir_mensah`. This is an engine-layer fix, not a content-layer one, so it sits outside a simple precondition/content edit.
4. **Compliance rules and event narrative are not synchronized.** The board-construction compliance system (`compliance.ts`) already "knows" about Cavendish's conflict (via his `independence: 'questionable'` status) and surfaces it as a blocking error before the game even starts — but the event data has no awareness that this disclosure may have already happened, so mevent_01's "undiscovered conflict" framing can be pre-spoiled for every player, not just ones who remove him.
5. **Dead state fields with no update path.** `founderSyndromeScore`, `charityCommissionInquiryActive`, and `solvencyRisk` all exist on `GameState` and are referenced by event copy or trustee risk-flag text as if they're live, but only `founderSyndromeScore` is even read (in two unreachable-in-practice branches); the other two are pure write-once-at-init dead fields. Any Tier 1 fix that wants to gate on "is there an active statutory inquiry" has no real flag to check yet — it would need to be wired up first.
