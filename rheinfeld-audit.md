# Rheinfeld AG — Scenario Logic Audit

**Scope:** AUDIT ONLY. No code or content was modified as part of this pass.

## Orientation

- **Events/scenarios:** [src/data/rheinfeld/events.ts](src/data/rheinfeld/events.ts) — 15 `GameEvent` objects (`revent_01`…`revent_15`), schema defined in [src/types/game.ts](src/types/game.ts) (`GameEvent` L211, `StrategyOption` L181, `OutcomeTierDefinition` L200, `FollowOnTrigger` L205).
- **Company/board shape:** [src/data/rheinfeld/company.ts](src/data/rheinfeld/company.ts) — `inheritedBoard` (L124-137: Heinrich as fixed chair, Margarethe + Strasser as removable shareholder NEDs, 5 fixed worker-rep seats), `committees` (L63-122, note `audit.chairDirectorId: null` and `nomination.chairDirectorId: 'rdir_heinrich'` at construction start), `eventSchedule` (L138-154).
- **Director data:** [src/data/rheinfeld/directors.ts](src/data/rheinfeld/directors.ts) — 12 seatable directors plus `rdir_12_reuter` (L421-443), a Meridian Capital nominee explicitly commented as "NOT in candidatePool — injected programmatically when the EGM settlement fires" and correctly absent from `company.ts`'s `directorIds` (confirmed).
- **Director dynamics:** [src/data/rheinfeld/dynamics.ts](src/data/rheinfeld/dynamics.ts) — 6 pairwise modifiers, all referencing seatable (non-fixed) directors; no board-state-fragility issues found here.
- **Board-state / lock mechanism:** [src/app/play/page.tsx](src/app/play/page.tsx) `BoardConstructionWrapper`. Two independent protection mechanisms for Rheinfeld, both wired at L1552 and L2195-2196:
  - `lockedDirectorIds={['rdir_heinrich']}` — Heinrich only. Confirmed lock-protected: cannot be removed, reassigned, or dragged pre-lock.
  - `workerRepIds={['rdir_w_koch','rdir_w_alrashid','rdir_w_hoffmann','rdir_w_mehta','rdir_w_gruber']}` — the 5 worker-rep seats. In [src/components/BoardroomTable.tsx](src/components/BoardroomTable.tsx) L618-621, `isWorkerRep` also drives `isNonInteractive`, so these seats are **equally locked** to Heinrich during board construction (not merely "non-assignable" in a soft sense — `onSeatClick` is disabled entirely, confirmed at BoardroomTable.tsx L644).
  - **Margarethe Rheinfeld (`rdir_margarethe`) and Dr. Wolfgang Strasser (`rdir_strasser`) are NOT in either protected set.** They are ordinary removable/reassignable NEDs, confirmed via `DEV_BOARD_RHEINFELD` (page.tsx L68-79) and the `BoardroomTable` props above. This makes them the actual risk surface for the A-class bug (see findings below) — not Heinrich, and not the worker reps.
- **Precondition engine:** [src/engine/gameStateManager.ts](src/engine/gameStateManager.ts) `checkEventPrecondition()` (L202-341) and `checkEventCondition()` (L372+). Unlike Meridian, Rheinfeld **does** use genuine board-state gates for some events:
  - `heinrichBlocks` (L272-278, gates revent_04): checks `state.board.seats.some(s => !inheritedIds.has(s.directorId))` — a clean, correct board-state gate (fires only if the player added a 9th+ seat beyond the fixed 8). No issues found here.
  - `meridianEGM` (L281-285, gates revent_12), `ceoConfidence` (L288-290, gates revent_14), `fullCrisis` (L293-297, gates revent_15) — all three key off `state.meridianStatus` and/or `state.heinrichConflictRevealed`. **These flags are never mutated anywhere in the codebase after initialization** (see the revent_12 deep-dive and cross-cutting finding below) — meaning all three gated events are structurally unreachable in every playthrough. Confirmed both by static analysis and by driving the actual game via `?dev=rheinfeld-q3` (see below).
  - `getCurrentEvent()` (gameStateManager.ts L164-198): if a precondition/condition fails, it returns `null` and the turn slot is silently skipped — no error, no replacement content, no visible sign anything was skipped. `handleAdvanceTurn` in page.tsx (L476-531) loops `advanceToNextTurn` until it lands on a firing event, AGM, or year-end, so the *game* doesn't break — it just quietly shows one fewer event than the schedule implies.
- **Compliance rules:** [src/engine/compliance.ts](src/engine/compliance.ts) `checkComplianceEU()` (L261-391) — German AktG/GCGC construction-time rules. Notable: Rule 3 `CHAIR_CHAIRS_NOM` (L340-346) tells the player during construction, in the compliance panel, that "Heinrich chairs the Nomination Committee... a significant governance concern noted by Meridian Capital" — this is real-world-accurate and doesn't spoil a secret event twist (revent_04 is about a specific blocked appointment, gated separately by `heinrichBlocks`), so it is **not** classified as a spoiler in the Meridian-pilot sense. Rule 4 `FORMER_EXEC_NO_COOLING` flags Strasser directly by name as a warning if he's seated — informational, not blocking, no event-reveal conflict found.
- **Event schema / templating:** [src/components/EventCard.tsx](src/components/EventCard.tsx) L144 renders `{event.narrativeCard}` verbatim — confirmed no interpolation/templating layer exists, identical to the Meridian pilot's finding. Names are hardcoded literal strings in `narrativeCard` / `outcomeTiers[*].narrative`.
- **revent_12 hardcoded-logic deep dive** (flagged by the user for special scrutiny) — see dedicated Finding below; short version: the removal logic at [page.tsx:368-392](src/app/play/page.tsx:368) is **not** hardcoded to specific director IDs the way Meridian's mevent_14 chair-swap was. It dynamically filters `newState.board.seats` by excluding worker-rep-prefixed IDs and `rdir_heinrich`, then removes the two lowest-tenure remaining seats. This is a *better*-engineered pattern than the Meridian bug class — but the entire code path is moot because `revent_12` can never fire (see below).
- **AGM/debrief content:** [src/components/AgmScreen.tsx](src/components/AgmScreen.tsx) — Rheinfeld-specific vote-adjustment math at L412-423 (`rRes1Adjustment`, `rRes3Adjustment`) and result-label narrative at L723-747 both read `gameState.heinrichConflictRevealed`, `gameState.meridianStatus`, and `gameState.workerRepRelations` — all three are dead/frozen fields (see cross-cutting finding), so this logic always executes its default/"nothing happened" branch in every game, regardless of player choices during Q1-Q4.

**Counts by suggested fix tier:**
- Tier 1 (precondition gate): 2 findings (revent_01, revent_04/08 — the latter also paired with Tier 2)
- Tier 2 (dynamic name injection): 0 standalone — recommended as a complement to Tier 1 on revent_04/08, same caveat as the pilot
- Tier 3 (cut/replace content or implement missing mechanic): 8 findings (revent_12, revent_14, revent_15, dead-flags cross-cutting, revent_15 "Game ends" sub-case, revent_09_c, revent_05_d, revent_11_d, Health Crisis/worker-rep finding)

**What makes Tier 1/2 fixes hard:**
1. **No per-strategy-option existence gating**, same as the Meridian pilot. `checkEventPrecondition` only gates whether the whole `GameEvent` fires; there is no equivalent at the `StrategyOption` level. revent_04's strategy A names Margarethe and Strasser directly in its description even though the schema has no `requiresDirectorId`/`requiresSeated` field to condition individual options on.
2. **Names are hardcoded in prose, not templated** — identical finding to the pilot. `narrativeCard` and `outcomeTiers[*].narrative` are plain strings rendered verbatim by `EventCard.tsx`; there is no `{{chairName}}`-style interpolation layer, so any Tier 2 fix requires building a templating pass, not just editing data.
3. **Company-specific `GameState` flags exist but have no update path wired to the events that are supposed to drive them.** This is the dominant failure mode in this audit (worse than in the Meridian pilot, where at least `founderSyndromeScore` was read in two dead-but-present branches): `meridianStatus`, `heinrichConflictRevealed`, `workerRepRelations`, and `csrdProgress` are all declared in `types/game.ts` with company-specific doc comments describing exactly what they should track, initialized once in `gameStateManager.ts`, and then simply never touched again by any `applyResolution`/event-effect code. Any Tier 1 fix that wants to gate revent_12/14/15 on real game history has no live flag to check yet — the flags need an actual mutation path added to the relevant events' resolution handlers first (revent_02/08/11/12 for Meridian status and the Heinrich reveal; revent_07 for worker-rep relations; revent_03/10 for CSRD progress) before any precondition or AGM-math fix built on top of them would do anything.
4. **The board-effect mutation layer in page.tsx is a single large sequential block of company- and event-specific `if` statements** (mevent_*, revent_*, sfgevent_* effects all interleaved from roughly L297-420), rather than a per-event effect hook. This makes it easy to add a new hardcoded check (as this file already does correctly for revent_12's dynamic seat filtering) but there is no structural guarantee that a *new* Tier 3 fix (e.g., wiring `heinrichConflictRevealed = true` into revent_11's resolution) will be discovered by whoever edits `checkEventPrecondition` later — the precondition and the effect that should satisfy it live in two different files with no cross-reference beyond comments.
5. **Generic engine mechanics (Health Crisis) are not aware of company-specific structural guarantees.** `checkHealthCrisis`'s exclusion list (`role !== 'chair'`) is copy-pasted logic that predates Rheinfeld's fixed-worker-rep-seat design; nothing in the engine enforces "these 5 specific directorIds are permanently protected regardless of which random mechanic fires." Any fix needs a shared protected-director-ID concept (parallel to `lockedDirectorIds`/`workerRepIds` in the UI layer) that the *engine's* forced-change logic can also consult, not just the board-construction UI.
